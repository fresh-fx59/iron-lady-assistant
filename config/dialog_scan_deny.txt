# The unit copies this file into place if the state-dir copy is missing, and

#
# The daily scanner (src/telegram_dialog_scan.py) QUARANTINES any new dialog that
# matches a rule here: it is reported to the operator but never enrolled into the
# news digest or the lead pipeline. Deleting a line REALLY DOES re-open that
# dialog: quarantined ids are tracked separately from enrolled ones and are
# re-evaluated against the current rules on every run. (Before 2026-07-30 they
# were written into the `seen` set and could never be re-evaluated — the file
# documented a behaviour it did not have.) A quarantine is reported the first
# time it fires and then only as a count, so it never pages nightly.
#
# Rule forms (one per line, `#` comments and blanks ignored):
#   @handle             deny by username (with or without the @)
#   handle              same thing
#   https://t.me/handle same thing — the form sources.txt itself uses
#   id:-1001609072825   deny by entity id; the marked (-100…) form your Telegram
#   id:1609072825       client shows and the raw positive form the proxy emits
#                       normalise to the SAME id, so either works
#   word:крипто         case-insensitive substring of the title OR any username
#   re:^travel          regular expression over "title + usernames"
#
# Handles match ANY of a peer's usernames (Telegram allows several), always
# case-insensitively. A rule that cannot be parsed (a typo'd regex, a non-numeric
# id, a line that is not a handle) is REPORTED in the run's ERRORS instead of
# silently denying nothing.
#
# Built-in defaults (DEFAULT_DENY_RULES_TEXT in the module) always apply and are
# the floor: the operator's personal channels @zhkparusa, @pifagortrade,
# @slezisatoshisliv2, @travelbelka_cards, @startupoftheday plus their keywords.
